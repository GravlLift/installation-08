`internal/mapmesh`, `internal/meshbuild` and `internal/mapref` are adapted from LevelUp's `internal/mapmesh` and `cmd/mapmesh-build` (AGPL-3.0, JGtm), rewritten to resolve and build a map mesh, a variant's object layer, a weapon model, the Spartan body, a single armor piece and a weapon's first-person rig in-process instead of through a child process and its own wire protocol. `internal/mapref` embeds reference data copied unmodified from LevelUp's `data/titles/halo_infinite/reference/` (the objectives catalog, the per-map background sidecars, the per-map geometry settings, the Forge material tints catalog `forge_materials.json` ~164 KB, and the Forge object visibility catalog `forge_objects.json` ~3.8 MB): measurements and catalogs built from publicly downloadable UGC map variants, not extracted from a local game installation. The variant builder's `--forge-materials` and `--forge-objects` flags override these embedded defaults with a different file when given; they are optional precisely because the defaults are shipped in the binary.

`internal/refdata/data/map_quant_bounds.json` is the map quantization bounds catalog (map display name, world bounds and per-axis quanta widths), copied from LevelUp's catalog producer `cmd/mapquant-build` and its measured catalogs (AGPL-3.0, JGtm): the bounds are measurements of the game's own level geometry (a map's own module, or its Forge canvas), not extracted assets. `internal/refdata/data/map_identity.json` is the map identity table keyed by the map asset id the film writes in chunk_00: display name, the normalized bounds-catalog key (the decoder's `NormalizeMapName` is the single rule from display name to key), and the geometry module key. It is generated from three LevelUp reference files (AGPL-3.0, JGtm): `.ai/V7.5/cartes/inventaire_rotation_ugc_2026-08-27.json` (the matchmaking rotation inventory: 104 maps with display name, module or Forge canvas), `apps/go-api/internal/service/testdata/map_ids_joues_20260827.json` (the map asset ids of played matches, frozen 2026-08-27, display names only), and the name-to-module table written in `apps/go-api/cmd/mapquant-build/main.go` (the level_id proofs that key the bounds catalog). The table holds 171 asset ids; 148 resolve to a bounds entry, 170 to a module key; the 23 without a bounds entry and the 1 without a module key (list in `TestMapIdentityCoverage`) degrade to a `--map` prompt or an unproven module, never a wrong decode.

`internal/mapmesh/spartan.go`'s `BodyAnimations` list is copied from LevelUp's `internal/mapmesh/meshproto` (`animationsDuCorps`, the body-only prefix of its `AnimationsSpartan`): names are the game's own animation identifiers, not game assets. Armor piece coatings (the community Ekur reference, a JSON export external to both LevelUp and this repo) and the per-weapon third-person reload/fire animation catalog are not ported; see the build-piece and build-spartan rows of docs/REFERENCE.md's One-time builds.

Code ported from Ekur (Copyright (c) 2026 The Halo Archive, GPL-3.0-or-later, https://github.com/TheHaloArchive/ekur, release 1.3.1): the rule that picks which sections of a Forge object's `mode` model to draw (the permutation named after the object's representation, else the region of that name), translated from Ekur's Blender add-on (`addon/src/operators/forge_map_operator.py`) into `third_party/map-images/himap/origine_forge.go`, which keeps Ekur's copyright notice; and the resolution of a layered material's look through the game's style tables (style list, palette, swatch), following Ekur's `material_coating.rs`, in `third_party/map-images/himap/couches_style.go`, which also keeps Ekur's copyright notice. GPL-3.0-or-later code can be combined with this project's AGPL-3.0.

The coating reference is built straight from the user's own game installation: `internal/ekurport` translates parts of Ekur 1.3.1 by TheHaloArchive (https://github.com/TheHaloArchive/ekur, Copyright (c) 2026 The Halo Archive, GPL-3.0-or-later) and follows the tag reading approach of infinite-rs 0.13.2 (Surasia, Unlicense OR MIT); the ported files keep Ekur's copyright line, and GPL-3.0-or-later can be combined with this project's AGPL-3.0. It is run automatically when the server starts without a valid export (and `IT3D_EKUR_DIR` is unset) and by hand through the `setup-coatings` command, always into the user's data directory; nothing is downloaded, and the ReclaimerFiles lists (https://github.com/TheHaloArchive/ReclaimerFiles) are no longer used. It writes the same five parts an Ekur export has (`materials/`, `stylelists/`, `styles/`, `globals.json`, `visor_data.json`), which are game-derived and stay in the data directory, never in the repo. When `IT3D_EKUR_DIR` names an existing Ekur export, the app uses it and never writes its own.

`internal/weapons` builds the whole weapon library (every `weap` tag of the installed game, the grenade projectiles, and the Spartan body) by reusing the same per-model builders `internal/mapmesh` already uses for `build-weapon` and `build-spartan`; it copies no additional game data and embeds no new reference files. The roster it reads is the game's own `weap` tags, exposed by a LOCAL-CHANGE in the vendored `himap` module (`third_party/map-images/himap/arsenal_roster.go`, registered in `third_party/README.md`). Built GLBs land in the data directory (gitignored), never in the repo.

`internal/refdata/data/weapon_names.json` is the weapon name table (weapon_key to English and French display name), projected from LevelUp's `config/titles/halo_infinite/mappings/weapon_names.toml` (AGPL-3.0, JGtm). `internal/refdata/data/replay_labels.json` is the replay label table (grenade ranks, ability palettes with markers and families, shot effects/tints/impacts, equipment object families, objective object identities, flag return zone, vehicle family qualifications, ability impulse/charge families), projected from LevelUp's `config/titles/halo_infinite/mappings/replay_labels.toml` (AGPL-3.0, JGtm). `internal/refdata/data/weapon_icons_tags.json` is the weapon icon tag table (weapon family to HUD icon stem), projected from LevelUp's `apps/go-api/internal/games/halo_infinite/weapon_icons_table.go` (AGPL-3.0, JGtm). `internal/refdata/data/equipment_energy.json` is the equipment energy catalog (per-sofa energy costs and thresholds read from the game's eqip tags), copied unmodified from LevelUp's `data/titles/halo_infinite/reference/equipment_energy.json` (AGPL-3.0, JGtm). The family-to-weapon-key join and the weapon-key-to-role table in `internal/refdata/labels.go` are hard-coded from LevelUp's weapon registry (`apps/go-api/internal/games/weapons/registry.go`, AGPL-3.0, JGtm). Together these feed the `replay.LabelCatalog` and `equipenergy.Catalog` the decoder consumes to name weapons, grenades, abilities, equipment, and objective objects in the replay document.

`internal/wwvorbis` is a Go port of ww2ogg by hcs (https://github.com/hcs64/ww2ogg, BSD-3-Clause style, Copyright (c) 2002 Xiph.org Foundation, Copyright (c) 2009-2016 Adam Gashlin) and embeds ww2ogg's aoTuV 6.03 packed codebook library (`packed_codebooks_aoTuV_603.bin`) unmodified; see `third_party/ww2ogg/NOTICE.md` and the license text in `third_party/ww2ogg/COPYING`. It repacks the announcer lines and the weapons' reload sounds, which are extracted from the user's own installation into the data directory, never shipped.

The web viewer ships the Basis Universal transcoder (`assets/basis_transcoder.js` and `assets/basis_transcoder.wasm`, Copyright Binomial LLC, Apache License 2.0, https://github.com/BinomialLLC/basis_universal), copied unmodified at build time from the `three` npm package (`examples/jsm/libs/basis`) so three's `KTX2Loader` can read GPU-compressed (KTX2) map textures without fetching anything from another site.

`internal/sounds/files/halo_infinite/` is the replay sound set (157 `.ogg` files), copied unmodified from JGtm's LevelUp (AGPL-3.0, https://github.com/JGtm/LevelUp, `static/sounds/halo_infinite`) and embedded in the binary by `internal/sounds` so the viewer plays match sounds on a fresh install. The set was hand-produced for a replay player (decoded, assembled and picked by ear) from Halo Infinite's game audio, which belongs to Microsoft / Halo Studios; the files are not game assets as distributed by the game, but they derive from it, and `import-sounds` remains the way to replace individual files with the user's own versions. Two files the viewer never requested (`impact_banshee_bomb.ogg`, `impact_wraith_mortar.ogg`) were removed outright (2026-11-17). The repair field's activation and end, the Spartan's weapon stand-and-drop sounds, the weapon and equipment stand appearance sounds, Assault's bomb detonation, and nine of Oddball's and Strongholds' objective calls (24 files) were removed the same day: `internal/eventsounds` now extracts them from the user's own installation, the same way `internal/announcer`, `internal/reloadsounds`, `internal/footstepsounds`, `internal/uisounds` and `internal/ambience` already did. One more file, `end_defeat_voice_en_01.ogg`, was removed the same day: `internal/endmatchvoice` extracts it from the installed game's own announcer catalog by a confirmed duration match (no Wwise id was ever documented for the end-of-match/round-over voice lines; the rest of that family — the second defeat take, the tie and victory lines, every French line, and round_over_en/fr — stay shipped because the install's catalog either has nothing within 15ms of them or ties two shipped durations to the same line).
